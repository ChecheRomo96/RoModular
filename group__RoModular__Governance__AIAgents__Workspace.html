Clone the ecosystem and configure a shared Codex or Claude workspace.

Purpose

RoModular provides equivalent shell and PowerShell entry points for creating the complete multi-repository workspace:

  • scripts/bootstrap-workspace.sh for macOS and other POSIX environments.
  • scripts/bootstrap-workspace.ps1 for Windows PowerShell.

Both scripts consume the same repository manifest and install the same workspace-level Codex and Claude adapters. Platform wrappers contain only the behavior required by their native shell.

Repositories

The checked-in .romodular/workspace/repositories.txt manifest currently defines these local directories:

Directory Repository
RoModular Ecosystem portal and governance
RoModularAgents Provider-neutral agent contracts, adapters, and skills
RoModularBuild Shared build infrastructure
Foundation Low-level C++ library
DspCore Signal-processing library
MCC Music Composition Core
MIDILAR MIDI protocol, translation and devices

Directory names are independent from remote repository names. For example, the MCC directory clones the MusicCompositionCore repository.

Usage

By default, a standalone checkout creates a sibling directory named RoModularWorkspace. When the active RoModular checkout is already inside an initialized workspace, the script reuses that parent directory. The destination remains configurable with --root, -Root, or the ROMODULAR_WORKSPACE_ROOT environment variable.

The default result is:

RoModularWorkspace/
|-- .romodular-workspace
|-- AGENTS.md
|-- .codex/
| `-- skills/
|-- .claude/
| |-- CLAUDE.md
| `-- skills/
|-- RoModular/
|-- RoModularAgents/
|-- RoModularBuild/
|-- Foundation/
|-- DspCore/
|-- MCC/
`-- MIDILAR/

macOS:

./scripts/bootstrap-workspace.sh

Preview the operation without writing files:

./scripts/bootstrap-workspace.sh \
--root "$HOME/Developer/RoModularWorkspace" \
--dry-run

Windows PowerShell:

./scripts/bootstrap-workspace.ps1

Preview the Windows operation with -DryRun:

./scripts/bootstrap-workspace.ps1 `
-Root "$HOME/Code/RoModularWorkspace" `
-DryRun

Safe Existing-Checkout Behavior

For every manifest entry, the scripts:

  1. Clone a missing repository with its pinned Git submodules.
  2. Verify the origin URL when the directory already contains a Git worktree. The equivalent HTTPS forms with or without a trailing .git suffix are accepted.
  3. Leave every existing repository, branch, worktree, submodule, and uncommitted change untouched.
  4. Refuse a directory that is not a Git worktree or has an unexpected origin.

The bootstrap never runs pull, checkout, reset, clean, merge, or rebase. It is therefore safe to preview against an active development workspace. A repository that requires synchronization remains an explicit maintenance decision.

Agent Configuration

The script installs two provider adapters and two discovery views backed by the same canonical instructions:

  • AGENTS.md at the workspace root is the Codex-compatible entry point.
  • .claude/CLAUDE.md is the Claude Code entry point and imports the root AGENTS.md instead of duplicating its contents.
  • .codex/skills/ contains generated Codex-discoverable copies.
  • .claude/skills/ contains generated Claude-discoverable copies.

Templates and skills are sourced from the cloned RoModularAgents repository. The shared entry point loads its canonical contract and the adapter belonging to each repository placed in scope.

Existing workspace instructions are never overwritten silently. When a different adapter already exists, the operation fails and preserves it. --force-config on macOS or -ForceConfig on Windows is required to replace either file or generated skill bundle deliberately. Canonical skills are edited only under RoModularAgents/skills/.

When the codex executable is available, the script prints the detected version and the workspace launch command:

codex -C "/path/to/RoModularWorkspace"

When claude is available, it prints the equivalent command launched from the workspace root. Claude Code discovers .claude/CLAUDE.md, which uses its supported @path import syntax to load AGENTS.md.

The bootstrap does not install Codex or Claude Code, sign into either service, modify user-level configuration, or store credentials. A missing optional agent is reported without making repository setup fail.

Options

macOS Windows Meaning
--root <path> -Root <path> Override the default RoModularWorkspace root
--manifest <path> -Manifest <path> Use an alternate repository manifest
--force-config -ForceConfig Replace differing workspace instructions and generated skills
--dry-run -DryRun Preview without filesystem changes

The ROMODULAR_WORKSPACE_ROOT environment variable supplies the root when the corresponding command-line option is omitted.

Arduino Libraries

scripts/install-arduino-libraries.sh and scripts/install-arduino-libraries.ps1 clone the runtime libraries into an Arduino libraries folder, using the origins from the same manifest:

./scripts/install-arduino-libraries.sh "$HOME/Documents/Arduino/libraries"
./scripts/install-arduino-libraries.ps1 "$HOME\Documents\Arduino\libraries"

Foundation, DspCore, MCC and MIDILAR are installed, in dependency order. A MIDILAR clone made before release 0.2.0, which tracked the rebuild branch, is switched back to main. Each library is a Git clone named after its Arduino library. Running the script again fast-forwards every existing clone with the expected origin to the latest commit of its branch; clones with local changes or diverged history are reported and left as they are. Any other existing folder is refused unless --force or -Force replaces it. --include-legacy and -IncludeLegacy are still accepted and have no effect. --dry-run or -DryRun previews the operation. Sketches must include <Foundation.h> and each library they use, such as <DspCore.h> or <MCC.h>. DspCore, MCC and MIDILAR on the Arduino AVR core require -std=gnu++17.
