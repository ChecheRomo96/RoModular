Detailed Description

Provider-neutral instructions for AI-assisted work across RoModular repositories.

Purpose

RoModular uses a shared operating contract so AI coding agents receive the same architectural boundaries, evidence requirements, and safety rules regardless of whether the active runtime is Codex, Claude Code, or another compatible tool.

The shared documents describe desired behavior. They do not require a particular model, vendor, or subagent implementation. A runtime may delegate a role to an isolated subagent or perform that role in the current session.

Structure

The RoModularAgents repository contains the canonical shared guidance:

RoModularAgents/
|-- AGENTS.md
|-- CONTRACT.md
|-- repositories/
|-- roles/
|-- workflows/
|-- skills/
`-- workspace/

AGENTS.md is intentionally a small router. CONTRACT.md, repositories/, roles/, workflows/, and skills/ are the source of truth. The same SKILL.md bundles follow the open Agent Skills format understood by Codex, Claude Code, and other compatible runtimes.

Repository Adapters

Every independently cloned repository needs a small root AGENTS.md because repositories do not automatically inherit instructions from sibling Git repositories. The adapter must:

  1. Look for ../RoModularAgents/ and read its AGENTS.md, CONTRACT.md, and matching repository adapter when available.
  2. Use the applicable shared skill for a repeatable workflow.
  3. Retain a complete local fallback for standalone clones.
  4. Define only repository-specific purpose, boundaries, supported commands, compatibility requirements, and validation rules locally.
  5. Report when shared guidance could not be loaded.

The relative sibling path is a convenience for the standard local checkout:

GitHub/
|-- DspCore/
|-- Foundation/
|-- MCC/
|-- MIDILAR/
|-- RoModular/
|-- RoModularAgents/
`-- RoModularBuild/

A standalone clone remains usable because its adapter contains the essential local rules. Shared guidance never expands the repositories or actions that the user placed in scope.

Roles

Role Responsibility Default authority
Architecture Auditor Repository ownership, dependency direction, and shared boundaries Read-only
Repository Maintainer Focused implementation and proportional validation Changes requested by the user
Release Auditor Version, CI, package, API, documentation, and release evidence Read-only
Documentation Curator Accuracy, navigation, status language, and rendered documentation Documentation changes requested by the user

A role defines responsibility and expected evidence; it is not permission to modify additional repositories, commit, push, tag, merge, publish, or release. Those actions still require explicit user authorization.

Workflows

The initial workflow set contains:

  • Repository audit: inspect repository state, declared contracts, implementation evidence, documentation claims, risks, and ordered next actions.
  • Release readiness: verify versioning, API changes, tests, packages, documentation, CI, platform evidence, and hardware-validation boundaries before recommending whether a release is ready.

Workflows complement each repository's checked-in scripts and presets. They do not replace build, test, install, export, or release automation.

Use Workspace Bootstrap to create a complete local checkout and the workspace-level entry point consumed by compatible agents.

Skill Distribution

The workspace bootstrap copies canonical bundles from RoModularAgents/skills/ into .codex/skills/ and .claude/skills/. These generated copies must not be edited directly. Rerunning the bootstrap with explicit force replaces them from the canonical source.

Sibling lookup cannot be assumed in CI, cloud workspaces, or standalone clones, so every repository retains a local fallback with its essential safety and compatibility rules.
